# SavtAssist — админ-панель

Веб-интерфейс для администраторов и операторов SAVT Assist. Работает поверх бэкенда на FastAPI; описание всех ручек — в [README-backend.md](README-backend.md). Код приложения лежит в папке [savt-assist/](savt-assist/).

## Стек

- Next.js 16 (App Router, `output: standalone`), React 19, TypeScript
- Tailwind CSS 4, компоненты на `@base-ui/react`, иконки `lucide-react`, уведомления `sonner`
- TanStack Query 5 для данных, Zustand для состояния интерфейса
- axios для запросов, Leaflet и react-leaflet для карты ШУ
- Node 22 в Docker-образе

## Запуск

Все команды выполняются в папке `savt-assist/`.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production-сборка
npm run start    # запуск собранного приложения
npm run lint     # ESLint
npx tsc --noEmit # проверка типов
```

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `https://helper.savt.by` | Адрес бэкенда. Подставляется при сборке в клиентский код и в `next.config.ts` |
| `BACKEND_NETWORK` | `savt-backend_default` | Имя внешней docker-сети бэкенда (только для `docker-compose.yml`) |

Локально переменная задаётся в `.env.local`:

```
NEXT_PUBLIC_API_URL=http://<адрес-бэкенда>
```

## Docker

```bash
cd savt-assist
docker compose build
docker compose up -d
```

- Контейнер `savt-assist-frontend` слушает порт 3000 и подключается к внешней сети бэкенда `BACKEND_NETWORK`.
- Адрес бэкенда задаётся при сборке: `NEXT_PUBLIC_API_URL=https://helper.savt.by docker compose build`.
- Наружу панель отдаёт nginx бэкенда через reverse proxy.

## Роли

| Роль | Что видит |
|---|---|
| `operator` | Раздел `/operator/*`: главная, проекты ШУ, заявки и рекламации (только просмотр), чаты, пользователи (без операторов и администраторов), база знаний, ЧаВо, карта регистров. Отвечает в чатах, меняет статус сервисных заявок, одобряет и отклоняет заявки (регистрация, сброс пароля, смена номера, добавление ШУ, доступ к документам); остальное — просмотр. Теги, синхронизация папок всех проектов, удаление и очистка чатов — только у администратора |
| `admin` | Раздел `/admin/*`: всё то же с правами правки, плюс очередь и удаление рекламаций, операторы и «Настройки» |
| `superadmin` | Всё, что у `admin`, плюс вкладка «Администраторы» и «Журнал действий» |

Что можно делать, определяет бэкенд; интерфейс скрывает недоступные действия.

## Разделы

| Раздел | Содержимое |
|---|---|
| Главная | Счётчики по заявкам, чатам и рекламациям, лента последних событий, карта ШУ |
| Проекты ШУ | Список проектов (поиск, сортировка, фильтры, список или сетка), карточка проекта со вкладками «Шкафы», «Документы проекта», «Пользователи», «Фото проекта», QR проекта и каждого ШУ, синхронизация папок на NAS |
| Заявки | Вкладки «Сервисные», «Добавление ШУ», «Документы», «Смена номера», «Смена пароля», «Регистрация», «Рекламации» (админ). Решения принимают администратор и оператор |
| Рекламации | Список и карточка в режиме просмотра для администратора и оператора (статус, гарантия, ответственный, срок приходят из Bitrix); повторная отправка в Bitrix недоставленных рекламаций, очереди «Не доехало до Bitrix» и «Карточку удалили в Bitrix», удаление — только у администратора |
| Чаты | Список чатов (закрепление, архив, поиск), переписка, вложения, голосовые, пересылка, закрепы, настройки вида |
| Пользователи | Вкладки «Пользователи», «Операторы», «Администраторы» (суперадмин); карточка с проектами и отдельно добавленными ШУ, отвязка доступа, верификация, блокировка |
| База знаний | Категории, записи, вложения, теги |
| ЧаВо | Категории и вопросы |
| Карта регистров | Описание битов регистров, переопределения по ШУ, выгрузка в Excel, живая телеметрия |
| Настройки | Рассылка уведомлений, рекламные заготовки и расписание, индексация базы бота |
| Журнал действий | Список действий администраторов с фильтрами и поиском |

Карточка ШУ открывается как окно со вкладками «Информация», «Документы», «Фото», «Пользователи», «Заявки», «Переопределения карты», «Лента событий».

## Вход и сессия

- Форма входа отправляет логин и пароль на `/api/auth/login` (route handler Next.js), он обращается к `POST /auth/admin-login`.
- `refresh_token` хранится в HttpOnly cookie `refresh_token`, `access_token` — только в памяти вкладки.
- При загрузке страницы `AuthBootstrap` получает новый `access_token` через `/api/auth/refresh`.
- На ответ `401` клиент один раз обновляет токен и повторяет запрос; если обновить нельзя, пользователь попадает на `/login`.
- `src/proxy.ts` перенаправляет неавторизованных с `/admin/*` и `/operator/*` на `/login`, а авторизованных с `/login` — в панель.
- Выход: `/api/auth/logout` отзывает токен и стирает cookie.
- Свой пароль меняется в меню профиля («Сменить пароль»); после смены все сессии закрываются и нужен новый вход.

## Работа с бэкендом

- Запросы идут на `/backend/*`; `next.config.ts` перенаправляет их на `NEXT_PUBLIC_API_URL`.
- Клиент — `src/lib/api/client.ts` (axios с заголовком `Authorization`, `authorizedFetch` для скачивания и загрузки файлов).
- Ошибки сервера (`{ "detail": ... }`) превращаются в текст функцией `apiErrorMessage` (`src/lib/api/errors.ts`); ответ `422` показывается общей фразой.
- Файлы (`/static/...`) отдаются по подписанным ссылкам, ссылка используется в том виде, в каком пришла от API.

## Обновление данных

- Данные кэширует TanStack Query, время свежести — 30 секунд; после мутаций связанные запросы сбрасываются.
- Списки заявок и рекламаций опрашиваются каждые 15 секунд на открытой вкладке; открытая карточка рекламации — каждые 15 секунд; очереди Bitrix — каждые 30 секунд.
- Главная опрашивается каждые 15 секунд, колокольчик уведомлений — каждые 10 секунд, карта ШУ — каждые 30 секунд.
- Чаты и телеметрия ШУ обновляются через Server-Sent Events (`src/lib/hooks/use-realtime-events.ts`, билет через `POST /operator/events/ticket`).

## Интерфейс

- Основные цвета: `#1B3A72` и `#4A8FE7`; темы — светлая, тёмная и праздничная (переключатель в шапке).
- Окна — `AppModal` (перетаскиваются, складываются в стек); подтверждения — `confirmDialog()` из `lib/store/confirm.ts`.
- Просмотр фото на весь экран — `ImageLightbox` и `PhotoLightbox`; QR проекта и ШУ — `QrDialog`.
- Состояние вкладок, видов (список или сетка) и панелей фильтров сохраняется в `localStorage` через `usePersistentState`.
